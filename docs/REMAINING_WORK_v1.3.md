# SafePass v1.3 추가 구현·제한·검증 안내

## 추가된 기능 (코드 기준, Cloudflare 실배포 미검증)
- 스테이징에서만 사용할 수 있는 관리자 인증 원클릭 데모 대여처 생성 API (`POST /api/admin/demo/setup`). `DEMO_TOOLS_ENABLED=true`로 활성화, 새 64자리 키 1회 발행, 데모 대여처 키 60분 만료, 생성 횟수 제한. 관리자 도구에 버튼 연결. 절대로 운영 Worker에 활성화하지 마세요.
- 관리자 감사기록 무결성 점검 (`GET /api/admin/audit-integrity`) 및 `audit_integrity` 해시 연결 기록. 이전에 작성된 `audit_events` 기록은 소급 검증되지 않습니다. 여러 요청이 동시에 기록될 때 완전한 순서 일관성을 보장하려면 별도 직렬화가 필요합니다. 따라서 법적 효력 있는 변경불가 원장이라 주장할 수 없습니다.
- 정기 정리: Worker Cron 매일 02:15 UTC 실행, `request_limits` 7일 이후 삭제, `demo_notices` 30일 이후 삭제. 기존 감사기록·미반납 심사 기록은 지우지 않습니다. 가상 신원정보는 생성 시 응답하며 별도 DB 테이블에 저장하지 않습니다.
- T09~T13 스테이징 전용 단계별 쓰기 통합시험 `tests/staging-e2e.mjs` 추가. 테스트를 실행한 실제 결과는 아직 없습니다.
- QR 이미지 인식에 브라우저 내장 `BarcodeDetector` 우선 사용, 미지원 브라우저는 기존 외부 라이브러리 사용.

## 미완료 또는 외부 승인 사항
- QR 스캐너 라이브러리의 완전한 자체 호스팅: 배포용 라이브러리 정식 파일과 라이선스 확인이 필요합니다. 외부 CDN 사용이 남아 있으며, 브라우저 네이티브 API는 지원되는 환경에서만 동작합니다. 네트워크 단절 시 QR 스캔의 보편적 동작은 보장되지 않습니다.
- 공식 모바일신분증 실연동: 제도·인증서버·사용 권한을 확보하지 못했으며 가상 인증·PIN만 제공합니다. 실제 신원확인 또는 실제 결제 보증이라고 표시하지 마세요.
- WebAuthn/생체 인증: 실제 인증 정보를 제공하지 않습니다. PIN 모의 인증 대체는 추후 사용자 등록·자격 증명 검증·복구 절차를 포함해 설계해야 합니다.
- 감사기록 원자적 해시 직렬화, 분쟁 대비 보존·파기 정책 및 법적 적법성 검토는 미완료입니다.

## 배포 순서
1. 운영 D1 백업 및 별도의 **스테이징** Worker/D1/Pages 프로젝트 준비.
2. 스테이징 D1에서 이전 스키마 상태 확인 후 `migrations/0003_audit_integrity.sql` 단 한 번 적용. `0001_init.sql`은 기존 D1에 재적용하지 않음.
3. 스테이징 Worker `ADMIN_KEY`, `TOKEN_SECRET`, `ALLOWED_ORIGIN`, `DB`를 검토, 스테이징에서만 `DEMO_TOOLS_ENABLED=true` 활성화.
4. Worker 배포 후 웹 Pages 배포. 자동화 시험에는 반드시 운영과 완전히 다른 주소 및 DB 사용.
5. 읽기 전용: `node tests/smoke.mjs https://<스테이징주소>`.
6. 쓰기 시험: `SAFE_PASS_STAGING_URL=https://<스테이징주소> SAFE_PASS_ADMIN_KEY=<관리자키> SAFE_PASS_ALLOW_WRITES=YES node tests/staging-e2e.mjs`.
7. 실패 없이 통과할 경우에만 운영에 단계적으로 적용. 운영에는 `DEMO_TOOLS_ENABLED`를 설정하지 않거나 `false`로 설정.

## 테스트 시 주의
- T12는 22초 기다리므로 전체 실행에 시간이 걸립니다.
- T09~T13은 스테이징 DB에 데이터를 생성하고 갱신하므로 비파괴 테스트가 아닙니다.
- 생성 데이터는 테스트 기록으로 남으며 키값은 출력하거나 기획서에 넣지 마세요.
- HTML/CSS 실기기 테스트, 복수 기기 동기화, 카메라 권한, QR 이미지 실패/성공, CORS, Worker 재배포 후 바인딩 점검은 별도 수행해야 합니다.

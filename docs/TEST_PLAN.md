# 시험 시나리오 및 검수 기준

| 번호 | 시험 | 기대 결과 |
|---|---|---|
| T01 | 대여처가 요청 생성 | SP1 코드 및 대여 건 ID 생성 |
| T02 | 유효 요청 조회 | 품목/기간만 반환 |
| T03 | 모의 PIN 틀림 | 401 차단 |
| T04 | 1234 입력 후 발급 | ACTIVE 1건 생성 |
| T05 | 동일 요청으로 재발급 | 409 차단 |
| T06 | 보증 검증 | valid=true, 신원정보 미포함 |
| T07 | 반납 완료 | RETURNED, 토큰 REVOKED |
| T08 | 반납 후 재검증 | valid=false |
| T09 | 기한 전 예외 열람 신청 | 409 거절 |
| T10 | 관리자 키 부재 또는 오류 | 401 거절 |
| T11 | 관리 키로 조회 | 감사 내역 조회 |
| T12 | QR 코드 변조 | 400 거절 |
| T13 | 다른 Origin에서 요청 | 403 거절 (Origin 헤더 있을 때) |

**테스트 미수행 상태**: 위 항목은 계획이며 실측 통과 결과가 아닙니다.

## 프로덕션 전 필수 과제
대여처 인증/권한 통제, 로그인, 개인정보 처리 영향 검토, 소비자 통지, 기기 인증/WebAuthn, 트랜잭션 원자성 검증, 재시도·동시성 검증, rate limiting, 실제 공식 모바일신분증 연계 가능 범위 확인, QR 스캔 및 QR 만료 정책, 데이터 보존/삭제 정책, 독립 보안검토.

## v0.2 추가 수동 시험

1. 모바일 HTTPS에서 카메라 권한 허용/차단, 후면 카메라 QR 인식 및 문자열 수동 입력 대체 동작.
2. 관리자가 승인하지 않은 PENDING 대여처로 대여 요청 생성 → 서버에서 차단되는지.
3. 관리자 APPROVED → 정상 요청 생성 → 이용자 모의 인증 → 대여처 검증 유효.
4. 대여처 SUSPENDED로 변경 후 검증/반납 처리 → 서버 403 거절.
5. 서로 다른 기기로 이용자/대여처 접속, 2.5초 폴링으로 상태 갱신 확인.
6. 반납 이후 기존 토큰 검증 → REVOKED, 재발급 시도 → 409 거절.
7. 예외 요청 관리자 심사 결정 후 개인정보 필드가 어떤 API 응답에도 포함되지 않는지 확인.
8. 시크릿 미설정, 잘못된 접근 키, 외부 Origin, 만료 요청 QR, 변조된 QR 차단 확인.

**검증 상태:** Node `--check`로 웹 JS 구문을 확인하고 `tsc --noEmit`로 Worker TypeScript 정적 검사를 수행했습니다. 실제 Cloudflare D1/Workers 연동, 카메라 실기기 및 E2E 브라우저 테스트는 아직 수행하지 않았으므로 위 목록은 실행 결과가 아닌 시험 계획입니다.

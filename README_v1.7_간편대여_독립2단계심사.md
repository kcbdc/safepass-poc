# SafePass v1.7 — 간편 대여·독립 2단계 신원정보 심사 (PoC)

## 핵심 변경
1. 대여자 모드 **홈**은 관리자 키 없이 진입합니다. 대여처 정보와 접근 키를 발급받은 후 QR 생성·검증·반납을 진행합니다.
2. 새로운 대여처 등록 시 서버가 고유 접근 키를 생성하고 등록 상태를 즉시 `APPROVED`로 설정합니다. 접근 키 해시만 D1에 저장합니다. 기존 APPROVED/REJECTED/SUSPENDED 상태를 임의 변경하지 않습니다.
3. **통합관리/미반납 이용자 조회**는 기존 `ADMIN_KEY` 인증을 요구합니다. 대여처 중지는 기존 관리자 기능으로 유지됩니다.
4. 미반납 정보 열람은 **관리자 1차 승인 → 별도 검토자 2차 승인 → 가상 신원정보 열람**입니다. 2차 승인은 `REVIEWER_KEY`가 별도로 필요하며, `ADMIN_KEY`와 같으면 무효입니다. 서버에서 상태·기한을 검증합니다. 감사기록도 남습니다.
5. 신원정보는 어디까지나 가상 시험 데이터이고 실제 모바일신분증 연동은 미구현입니다. 품목별 이용한도는 그대로 유지됩니다.

## 필수 Cloudflare 설정
- Worker Secret `REVIEWER_KEY`: `ADMIN_KEY`와 다른 강력한 임의 문자열 (예: 32바이트 이상 난수). 실제로 서로 다른 담당자가 관리해야 합니다.
- 기존 Worker Secret `ADMIN_KEY`, `TOKEN_SECRET` 및 D1 바인딩 `DB` 유지
- 기존 `ALLOWED_ORIGIN`, `DEMO_TOOLS_ENABLED` 유지
- Wrangler 배포에서 secret이 보존되는지 확인. `REVIEWER_KEY`를 GitHub 소스에 넣지 마세요.
- **배포 순서:** Worker 업데이트 → Pages 업데이트 → 새로고침

## 구 버전 DB 유의사항
과거 관리자 승인을 기다리던 `PENDING` 대여처는 자동 승인으로 바꾸지 않았습니다. 해당 대여처를 재사용하려면 기존 통합관리에서 관리자가 승인할 수 있습니다. 새로 등록하는 대여처부터 관리자 승인 없이 즉시 사용 가능합니다.

## 검증 시나리오
- 관리자 비로그인 상태에서 대여자 홈 진입 → 새 대여처 등록 → QR 생성 성공
- 발급된 접근 키가 없거나 틀린 경우 다른 대여처의 대여 건 검증·반납 불가
- 정상 대여에 기존 자전거/면접정장 등 기간·횟수 한도 유지
- 만료 전에는 신원 열람 심사 불가; 만료 후 1차 승인 전 열람 불가
- 관리자 1차 승인 후 2차 검토자 키 없이 열람 불가
- 독립된 2차 검토자 키로 2차 승인 후 **가상 신원정보** 열람 가능, 감사기록 저장
- 반납 후에는 심사/열람 불가

## 한계와 보안 안내
대여처 등록 즉시 활성화는 **PoC 편의 설정**입니다. 정식 운영에서는 사업자 검증과 접근 키 발급 제한/회수가 필요하며, 실재 신원정보 조회 연계 시에는 개인정보 처리 근거·목적 제한·권한자 분리·사전통지 등을 검토해야 합니다. 2개의 키를 화면 한 명이 입력할 수 있다는 사실만으로 실제 조직의 직무분리를 증명하지는 않습니다. 키는 서로 다른 권한자가 관리해야 합니다.

기존 `APPROVED_FOR_REVIEW` 기록은 2차 승인 감사기록이 없으면 열람되지 않도록 차단했습니다. 필요한 경우 관리자 정책에 따라 해당 건을 `PENDING_REVIEW`로 되돌려 1·2차 재심사하세요.
